A full-stack, automated audit and verification system designed for **B.Tech / MCA Major Projects**. The system accepts product label photographs, processes them through an OpenCV noise-reduction and binarization pipeline, extracts printed textual declarations using Tesseract OCR, parses key fields via Python Regex/NLP, and audits them against statutory requirements codified in a configurable Legal Metrology rule database.

---

## 1. Core Architectural Principle

> [!IMPORTANT]
> **"AI-based techniques are used mainly for OCR and text processing to extract information from product labels. The final compliance decision is generated by a configurable rule-based compliance engine."**

The system does **NOT** claim that AI "knows" or "interprets" statutory law autonomously. Instead:
- **Computer Vision & OCR** extracts printed package text.
- **Python NLP / Regex Normalizer** structures messy OCR text into validated entities (Product Name, MRP, Net Quantity, Manufacturer, Address, Grievance Care).
- **SQLite Rule Database** stores verified Legal Metrology provisions from official government notifications.
- **Rule Engine** applies deterministic validations to yield clear, explainable **PASS**, **FAIL**, or **REVIEW** outcomes.
- **ReportLab Engine** generates formal, audit-ready PDF compliance certificates.

## 2. Reviewer-Friendly Project Summary

When demonstrating or explaining this project to college reviewers, examiners, and evaluators:

> *"The user uploads a packaged commodity label. OpenCV preprocesses the image (grayscale, rescaling, Gaussian blur, and Otsu binarization) and Tesseract OCR extracts the printed text. Python-based text processing identifies important fields such as MRP, net quantity, manufacturer name, address, and consumer care details. These extracted fields are compared with applicable requirements stored in a configurable Legal Metrology rule database. The rule engine generates PASS, FAIL, or REVIEW results, calculates a quantitative compliance score, provides actionable reviewer recommendations, and produces a formal downloadable PDF compliance report."*

## 3. Technology Stack

- **Frontend:** HTML5, CSS3, JavaScript (ES6+), Bootstrap 5.3, Bootstrap Icons (clean, responsive dashboard UI with drag-and-drop file upload and live preview).
- **Backend Framework:** Python 3.11 with Flask.
- **Computer Vision:** OpenCV (`opencv-python`), Pillow (`PIL`).
- **Optical Character Recognition (OCR):** Tesseract OCR via `pytesseract`.
- **Text Extraction & NLP:** Python Regular Expressions (`re`), line-by-line semantic heuristics, unit standardizers.
- **Relational Database:** SQLite 3 (built-in Python `sqlite3`) storing rules and historical audit logs.
- **Audit PDF Generator:** ReportLab (`reportlab.platypus`).
- **Testing:** Python `unittest` test suite covering preprocessing, OCR, entity extraction, compliance scoring, and PDF generation.

## 5. Verified Legal Metrology Statutory Sources

This system avoids unverified web scraping. Every rule in `rules.db` is directly mapped to official publications of the Department of Consumer Affairs, Ministry of Consumer Affairs, Food & Public Distribution, Government of India:

| Rule Code | Regulated Field | Statutory Reference | Standard Validation |
| :--- | :--- | :--- | :--- |
| **LM001** | Product Name / Commodity | Rule 6(1)(a), Packaged Commodities Rules 2011 | Must declare generic or common commodity title |
| **LM002** | Net Quantity | Rule 6(1)(b) & Rule 12, PC Rules 2011 | Standard metric units (`g`, `kg`, `ml`, `l`, `mg`) |
| **LM003** | Maximum Retail Price (MRP) | Rule 6(1)(e), PC Rules 2011 | Numeric value > 0 inclusive of all taxes |
| **LM004** | Manufacturer Name | Rule 6(1)(d), PC Rules 2011 | Name of manufacturer, packer, or importer |
| **LM005** | Manufacturer Address | Rule 6(1)(d), PC Rules 2011 | Complete physical factory or premises address |
| **LM006** | Consumer Care Grievance | Rule 6(1)(n), PC Rules 2011 | Contact channel (Helpline phone or Email address) |

## 7. Tesseract OCR Windows Configuration

The system is configured to look for Tesseract OCR in its standard 64-bit Windows installation folder:
```text
C:\Program Files\Tesseract-OCR\tesseract.exe
```

### Installing Tesseract OCR on Windows:
1. Download the official Windows installer from UB-Mannheim:
   - **Download Link:** [https://github.com/UB-Mannheim/tesseract/wiki](https://github.com/UB-Mannheim/tesseract/wiki)
2. Run the installer (`tesseract-ocr-w64-setup-5.x.exe`).
3. Install to the default location: `C:\Program Files\Tesseract-OCR`.
4. The system will **automatically detect** this path upon startup.

### Custom Tesseract Path (Optional):
If installed in a custom location, specify it in `config.py` or set an environment variable:
```powershell
$env:TESSERACT_PATH = "D:\Tools\Tesseract-OCR\tesseract.exe"
```

> [!TIP]
> **Zero-Crash Demo / Mock Mode:** If Tesseract is not installed yet on your system, the application **will not crash**. It displays a clear badge indicating `"OCR Mock / Demo Mode"` and allows complete testing using the built-in demo scenarios!

## 11. Important Legal Limitations

> [!WARNING]
> This application is a **software-assisted label verification tool**. It verifies information printed on the package label.
>
> It **does NOT physically verify**:
> 1. Actual physical weight or volume inside the container.
> 2. Product chemical or qualitative composition.
> 3. Authenticity or counterfeit prevention.
> 4. Physical container tare weight versus gross weight tolerances.
>
> For example: An empty sealed box with a perfectly printed compliant label will pass this software because the software validates printed statutory declarations.

## 12. Future Scope & Enhancements

For future research and expansion (e.g., M.Tech or commercial deployment):
1. **IoT Load Cell Integration:** Interfacing digital precision scales to measure gross package weight, subtract container tare weight, and compare against declared net quantity within statutory Maximum Permissible Error (MPE) tolerances.
2. **Barcode & GS1 2D DataMatrix Validation:** Cross-checking printed text with encoded GTIN barcodes to identify discrepancies between printed label and central product registries.
3. **Multilingual OCR:** Support for Devanagari (Hindi) and regional Indian language declarations using deep-learning TrOCR or paddleOCR models.
4. **Automated Gazetted Notification Crawler:** Web-monitoring scraper tracking official Gazette notifications published by the Department of Consumer Affairs for automatic rule version updates.
5. **Mobile Application:** Real-time on-device scanning using camera frames for field inspections by Legal Metrology Inspectors.
